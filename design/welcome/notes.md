# 安隅首次设置：三个方案

所有内容都在 `scratchpad/design/welcome/`：

- `index.html`：总览和截图墙
- `option-a.html` / `option-b.html` / `option-c.html`：每个文件自包含，从头到尾都能点
- `shots/{a,b,c}/`：截图。全部场景都有浅色 1280×800；关键场景另有深色 1280、浅色和深色 800×560，以及 Windows 标题栏和 720×480 各一张
- `src/`：原始文件。`build.mjs` 把公共的 CSS 和 JS 内联进三个方案，`shoot*.sh` 用无界面 Chrome 截图

每个方案页面顶部的条不属于产品：它可以跳到任意场景，切换深浅色、macOS/Windows、窗口尺寸，并决定演示时“获取订阅”和“核对”的结果。演示里的计时是加速的，1 个显示秒等于 250 ms。

参考过的其他浏览器：Tor Browser 首次启动的“连接 / 配置连接”二分，以及连接卡住时进入 Connection Assist（用网络搜索核对了官方文档）；Arc、Zen 的节奏和克制，Firefox about:welcome 的“跳过这一步”，这几个凭我已有的了解，没有逐一核对。只借结构，不借外观。

## 三个方案共用的决定

### 1. 放在哪、窗口外框怎么处理
设置页是正常窗口里的内部页，和设置页一样，不是弹窗也不是单独的窗口。**设置期间隐藏标签栏和工具栏**，因为：

- 闸门关着时什么都打不开。地址栏和标签页只会诱导用户做一件必然失败的事，而且失败的样子（空白页、错误页）恰恰是这个流程要避免的第一印象。
- 设置页占满整个窗口，用户就清楚“现在在设置”，不会把它当成一个普通标签页关掉，然后找不回来。

页面顶部保留一条 52px 的带子，在产品里是拖动区（`-webkit-app-region: drag`），上面的按钮设为 no-drag，点击范围就是按钮本身：
- macOS：交通灯左侧留 76px。建议设置期间把 `trafficLightPosition` 调到带子的竖直中心（y≈19）。
- Windows：`titleBarOverlay` 的标题栏按钮在右侧，留 138px。设置期间 overlay 高度用 40，带子仍是 52。
- 带子上只有：小标志、步骤指示（A）、“稍后设置”。

需要在 `window.ts` 加一个 setup 布局（页面区域等于整窗减去带子），代码改动在 shell，不涉及闸门。

### 2. “稍后设置”和“退出后重开”
- **稍后设置**：回到正常窗口。盾牌是红的；状态卡的修复区第一个按钮是“继续设置”（`condition-fix` 新增一个 `setup` 修复项）；主页搜索框下多一行“外网已关闭：设置还没有完成 · 继续设置”。见场景 `later` 和 `later-partial`。
- **退出后重开**：已导入的来源、选中的节点、出口国家本来就存在 profile 里。只有还没提交的草稿（没点“获取”的链接、端口、当前步骤）需要另存一个 `setup` 记录。它不放进 profile，因为 profile 要能拷到别的电脑。重开时回到原处，并在顶部提示一句“上次设置到这一步，内容都保留着”。见场景 `resume`。
- 草稿里的订阅链接可能带 token，所以和 profile 存在同一个本地目录，不写日志。

### 3. 决策的顺序跟着闸门走
`gate.ts` 里的 `needsCheck` 要求先有出口国家才会去核对，节点的国家也要核对过才知道（`NodeState.country` 在核对之前是空的）。所以顺序只能是：**选节点 → 填国家 → 核对**。
- 节点名里能看出国家时，预先选好国家，并写明“按节点名称推测，以实际核对为准”（场景 `node`）。
- 看不出来时不猜，必须由用户自己选（场景 `node-unknown`）。
- 用本机代理软件时没有节点可选，只填国家（场景 `node-external`）。

### 4. 网络请求：两次，都由用户触发，都事先说明
欢迎页和整个设置过程都不联网，没有任何为了装饰而加载的资源，图标和标志都内联。只有两个动作会发请求：
1. **获取节点**（订阅链接）：从本机**直连**订阅地址一次，不经过代理，因为此时还没有代理可用。旁边写着：“获取时，安隅会从这台电脑直接访问这个链接一次，不经过代理……不想发出这一次请求，可以改用文件或粘贴。”文件和粘贴明确标注“不发网络请求”。
2. **核对出口**：第一次经代理的请求，只访问核对地址。核对前写明这一点。

“测速”也会经内核发出请求，只有用户点了才会测。

### 5. 核对过程不造假
- 只显示闸门真实的条件，来自 `gateConditions`：**代理核心 / 节点**（external 方式下是**本机代理端口**）**/ 出口国家**。“外网开关”这一行在设置期间省略，因为它一直是开着的。
- 正在做什么写成具体的话：“正在经 日本 东京 01 访问核对地址，读出出口 IP 和国家 · 已等待 4 秒”。用呼吸的点（现有的 `.dot.checking`），不用无限转圈的图标。
- 15 秒算超时。**这个数字要和真实的核对超时一致**（见问题 5）。
- 核对通过后说明以后会怎样：“之后每次换节点、每隔 5 分钟都会重新核对；不一致就立刻关闭外网。”

### 6. 每个失败状态都说明是哪一项、该怎么办
| 状态 | 提示 | 操作 |
| --- | --- | --- |
| 订阅获取失败 | 主机名 + 返回码 + 通俗原因 | 再试一次 / 改用文件 |
| 来源里没有节点 | 只认 Clash YAML 的 `proxies`；在服务商处选“Clash”格式的链接 | 改用粘贴 / 改用订阅链接 |
| 出口不一致 | 实测 X（IP），设置要求 Y；节点名和实际出口不一定相同 | 换一个节点 / 改为 X（即现有的 exitFix） |
| 本机端口无回应 | 127.0.0.1:7890 上没有软件在监听，检查端口和协议 | 再试一次 / 修改端口 |
| 核对超时 | 15 秒内没有结果，节点可能失效或太慢 | 再试一次 / 换一个节点 |
| 代理核心未运行 | 核心是自带的本机程序 | 重新启动核心（`restartAndCheck`）/ 复制报告 |

### 7. 身份跟着出口走，离线算出
- 时区：`new Intl.Locale('und-JP').getTimeZones()`。国家有多个时区时（美国）给出下拉框。
- 语言：`new Intl.Locale('und-JP').maximize()` 得到 ja-Jpan-JP，取 ja-JP 和 ja。
- 位置：默认“拒绝”（`geolocation: null`，现有语义就是拒绝定位请求）；可选“报告某城市市中心附近”，这需要内置一张小的城市坐标表。
- 平台：不动，保持“跟随本机”。
- 只写 `timezone / locale / acceptLanguages / geolocation`，走 `updateProfile`，和 EnvSection 的保存一样。界面语言不受影响。
- “保留现在的设置”也是一个正当选择，但要说清后果（网站会看到时区和 IP 所在地不一致）。

### 8. 键盘、焦点、点击范围
- 每一步换页后焦点移到标题上；Enter 触发主操作；Esc 不做任何事，因为这不是对话框。
- 核对列表加了 `aria-live="polite"`，读屏会依次读出每一项的变化。
- 焦点环一律用令牌：`1.5px solid var(--accent)`；实心主按钮和单选框的焦点环外移 1px，和 style.css 一样。
- 点击范围和装饰分开（AGENTS.md 第 15 条）：卡片式选项的点击范围就是卡片的边框盒，它没有阴影，选中态只是描边加底色。展开的清单行（C）同样只有描边。截图里唯一的阴影是“稍后设置”里现有的工具栏状态卡，产品里它按第 15 条画在单独一层。
- 深色模式用的是 style.css 里的深色令牌。截图逐张看过，次要文字 `--text-2 #a6a7aa` 在 `#232325` 上对比足够。

### 9. 中英文
界面以中文为主。第 1 步（欢迎）和第 3 步（节点、出口国家、核对，包括全部失败状态）有完整英文，可以在欢迎页切换，或者看 `*-en` 场景。其余步骤目前只有中文。

## 方案 A：逐步引导（一屏一步）
**结构**：居中单栏，宽 560。顶部带子中间是步骤指示：五个带圆圈的标签，窗口窄于 940 时换成“第 2 步，共 5 步 · 连接”。底部固定一条操作栏，“上一步”在左，主操作在右。欢迎页是一屏居中的标志、名称、一句话、语言、“开始”。

**擅长**
- 最平静、最容易看懂，节奏接近 Arc 和 Zen。每屏真正只有一件事。
- 实现最简单：一个 Preact 页面加一个步骤状态，各步直接复用设置页的控件。
- 小窗口下也最稳，720×480 能用（节点列表在页内滚动）。

**代价**
- 用户看不到全貌：不知道后面还有什么，也不知道为什么非得做完才能上网。
- 向导是一套独立的状态（当前在第几步），和闸门的状态（哪些条件已满足）是两套东西。比如用户在设置页里换了节点，向导并不知道。重开后的恢复、部分完成的处理都要额外写逻辑。
- 设置完就丢掉了。之后关闸时，用户在状态卡里看到的是另一种样子，等于要再学一次。

**复用**：`ConditionList` 的行（放大）、`condition-fix`、`.nodes.compact` 节点列表、添加订阅（`sub-url` / 文件 / 粘贴）、external 字段、`theme-picker`、标签页布局卡片、搜索引擎下拉框、书签导入。

## 方案 B：双栏（左边做，右边看）
**结构**：左栏放步骤内容，顶部有分段进度和“第 n 步，共 5 步”。右栏宽 340，窗口窄时 296，是**实时状态卡**：`GateSummary`，加上条件行（代理核心 / 节点来源 / 节点 / 出口国家），再加一组“网站看到的身份（不影响放行）”。当前这一步对应的那一行会高亮。核对时左边只写“正在做什么、等了几秒”，结果和修复办法也在左边，条件行在右边原地变化。

**擅长**
- 最能讲清闸门是怎么回事：第一屏就看到“外网关着，因为还没有节点”。之后每做完一步，右边就亮一行。
- 右栏就是以后工具栏状态卡的放大版。设置结束时，用户已经学会怎么看它。
- 身份单独成组，标明“不影响放行”，把“必须满足的”和“建议的”分开了。

**代价**
- 吃宽度。800 宽时左栏内容区只有约 436px；720×480（真实的最小窗口）时右栏只能收成一条细栏，方案的意义就没了。
- 用户要看两个地方。身份那一步左右两边的信息有重复。
- 需要扩展 `gateStatus`，加上“节点来源”和身份几行，组件要改得比 A 多。
- 和 A 一样，向导状态和闸门状态是两套。

**复用**：`GateSummary`、`ConditionList`（多两行）、`condition-fix`，以及和 A 相同的各步控件。

## 方案 C：放行清单（状态卡放大成整页）（推荐）
**结构**：单栏，宽 640。欢迎时页面顶部是标志、名称、一句话、语言、“开始设置”。下面是一条吸顶的摘要（`GateSummary`，加上“放行条件 2/4”），再下面是清单：

1. 代理核心：自动完成，一开始就是 ✓（本机程序，不联网）
2. 代理来源：展开后先选方式，再填订阅、文件、粘贴或本机端口
3. 节点：external 方式下显示“由你的代理软件决定”，没有可操作的内容
4. 出口国家：先填国家，再“核对出口”，核对过程和结果都在这一行里

“建议（不影响放行）”：
5. 身份与出口一致
6. 个性化（可选）

每次只展开一项。完成的项收起成一行摘要，带“更改”。展开的项自动滚到吸顶摘要的下方。步骤指示就是清单本身：每行的数字或 ✓，加上“2/4”。“上一项”回到上一行。

**擅长**
- **设置和状态是同一个结构**（AGENTS.md 第 14 条）：清单的每一行由闸门条件推出来，不另外记“当前在第几步”。所以不会出现“向导说完成了，闸门却还关着”。退出重开、稍后再来、只做了一半、以后某个条件失效，都不需要额外逻辑：打开的永远是第一项没满足的条件。
- 一开始就如实告诉用户要满足哪几项，和 Tor 的诚实进度是同一个思路；第一项已经打勾，用户心里有底。
- 以后关闸时，“设置 › 状态与检查”和工具栏状态卡可以直接用这张清单修，不会留下一个用完就扔的向导。
- 一行一个决定：节点和国家各占一行，核对就在国家那一行里进行。

**代价**
- 页面比 A 长，要处理滚动：摘要吸顶，展开的行自动滚到摘要下方。800×560 下打开的行占了大部分屏幕，上面已完成的行要往回滚才能看到。
- 新手一次看到的字比 A 多。欢迎时不如 A 有仪式感。
- “代理来源”一行里分两段（先选方式，再填内容），比 A 多一层。

**复用**：`GateSummary`、`ConditionList`（每行变成可展开的）、`condition-fix`，以及和 A 相同的各步控件。产品里可以让它和设置页的状态区共用一个组件。

## 推荐
**推荐 C，节奏上借 A 的克制。**理由是结构上的：只有 C 让“设置流程”和“闸门状态”成为同一个东西。A 和 B 都维护一套“第几步”的状态，它会和真实的闸门条件分叉，恢复、部分完成、以后条件失效，都要靠额外的代码去对齐。C 的每一行由条件推出，这些情况天然就对，而且以后关闸时的修复界面也是这张清单。B 能教会用户闸门的概念，这一点 C 也能做到，因为 C 本身就是那张卡；但 B 在 720 宽时会失去意义。

如果你更看重第一次见面的仪式感，可以让 C 的欢迎页像 A 一样单独占一屏，点“开始设置”后再进入清单。这个变化很小，不影响结构。

## 需要你决定的问题
1. **首次获取订阅只能直连。**主进程允许在闸门关闭时直连获取（`gatekeeper.addSubscription` 只拦 `via === 'proxy'`），但设置页现在在外网关闭时把“获取节点”按钮禁用了（`settings/view.tsx`：`state.gate.state !== 'open'`）。设置流程需要允许这一次直连请求，并像上面那样如实告诉用户。你同意吗？还是首次设置只允许文件和粘贴？
2. **出口国家怎么填。**现在的闸门必须先有国家才会核对。可以接受“按节点名推测，并标明是推测”吗？还有一个更好的做法：增加一次“只测量、不放行”的探测（闸门保持关闭，结果只用来预填国家），用户就不用猜。但这要改 `gatekeeper.ts`，需要你明确授权；它不会让闸门更宽松，只是多一次测量。
3. **设置期间隐藏标签栏和工具栏**（需要 `window.ts` 加 setup 布局，并调整交通灯和 Windows 标题栏按钮的位置），同意吗？
4. **身份的默认值。**网站首选语言默认“只按出口”（ja-JP, ja），还是“出口语言优先，再加中文”？位置默认“拒绝”还是“城市附近”（后者要内置一张城市坐标表）？多时区的国家默认选哪个时区？
5. **核对超时的真实数值是多少？**界面写的 15 秒必须和实现一致。另外，超时后要不要自动重试一次？
6. **界面语言的预选。**系统语言既不是中文也不是英文时，默认英文可以吗？
7. **个性化一步要不要“导入书签”？**它只能从 HTML 文件导入，对多数人来说多了一步导出，也可以挪到完成页做一句提示。
8. **Windows 的“备选模式”**只在 Windows 的“连接方式”一步加一句提示，正式切换放到设置里，这样够吗？
9. **如果选 C**，是否同时让“设置 › 状态与检查”和工具栏状态卡共用这张清单（关闸时直接在清单里修）？这会改动现有的状态页。
10. **最小窗口。**任务写的是 800×560，代码里实际是 720×480（`window.ts` 的 minWidth/minHeight）。按哪个为准？三个方案在 720×480 都截了图：A 和 C 能用，B 的右栏会收起。

## 3. 重新打开时显示哪一步：从真实状态推出，不存步骤号
A 保留“当前步骤”，但这个步骤**每次打开时由 profile 和闸门状态推出**，不读任何存下来的步骤号。顺序就是闸门条件的顺序：

1. 从没点过“开始” → 欢迎。
2. 没有来源（system 方式）或端口为 0（external 方式）→ 连接（用户之前选过路径的话，直接到添加节点 / 端口那一屏，草稿还在）。
3. 没有选中的节点，或 `egressCountry` 为空 → 节点和出口国家。
4. 闸门不是 open → 核对。这一屏自己会显示内核在启动时自动进行的那次核对（场景 `reopen-verify`），用户什么都不用点。
5. 闸门 open，但身份那一步还没确认或跳过 → 身份。
6. 个性化还没完成或跳过 → 个性化。
7. 都满足 → 不显示设置，直接进正常窗口。

只额外存两样东西，都是“用户做过的选择”，不是位置：身份、个性化是否已处理（它们不是闸门条件，profile 里看不出来），以及没提交的草稿（选过的路径、没点“获取”的链接、端口）。

保证向导不会在闸门关着时说“完成”：
- 步骤条上的勾由状态决定，不由“走过”决定：「核对出口」只在闸门 open 时打勾。用户回到上一步换了节点，勾立刻消失。
- 在身份、个性化、完成这几步时，闸门一旦关闭（出口变了、内核停了），向导回到核对那一屏，显示真实原因。
- 完成页的「开始浏览」只在闸门 open 时可用。
- 演示里“稍后设置 → 继续设置”走的就是这套推导（`deriveStep`），不是回到上次停的位置。
