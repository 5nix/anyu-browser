# 真机手工测试（macOS 和 Windows）

自动测试只在 Linux 上验证两件事：进程的连接目标，以及引擎报告的配置值。字体、GPU、通行密钥、真实的宿主机 TUN 网卡、未签名包的安装流程，这些只能在真机上确认。下面每一项在 **macOS** 和 **Windows** 上各做一遍，结果记成通过、失败或备注。

准备：

- 一份能用的 Clash YAML 订阅，以及节点所在的国家码。
- 一个本地测试页。比如在任意目录下运行 `python3 -m http.server 8000` 后用 `http://127.0.0.1:8000`；或者用仓库里的 `node -e "import('./test/server.mjs').then(m=>m.startFixtureServer({port:8080}))"`。注意：Cave 默认拒绝本机和私网地址，所以本地页只用来在 **本机的普通 Chrome** 里做对照，或者在打开 `allowPrivateNetwork` 后访问局域网 IP。需要公网测试页时用 `https://example.com`。
- 把 `logs/core.log` 和自检的“复制报告”附到结果里。

## 1. 全新启动，网络关闭

删掉配置目录（或者设 `CAVE_PROFILE` 指向一个空目录）后启动。

- 预期：窗口打开，并打开设置标签页的“节点与订阅”；状态图标是红点，点开显示 **外网已关闭 · 还没有导入节点**。
- 在地址栏输入 `https://example.com`，页面不会发出请求，只弹出状态卡片，写明放行后会自动打开 example.com；不会盖住网页。
- 报告里“出口国家等于配置”这一项不通过。
- macOS：未签名包按 README 的步骤可以打开。Windows：系统安全检查放行后可以安装和运行；zip 便携版也能运行。

## 2. 导入节点并放行

导入本地 YAML，填国家码，再选一个节点。

- 预期：状态依次是“正在核对出口国家”和 **外网已放行**。
- 第 1 步留下的 `example.com` 标签会自动加载。
- 13 项检查里，除了“呈现的平台”之外都通过；platform 是 host 时，这一项也通过。

## 3. 杀掉内核

macOS 用活动监视器或 `kill -9`，Windows 用任务管理器，结束 `cave-core`。

- 预期：状态立刻变成关闭，正在加载的页面失败。大约 1 秒后内核会被重新拉起，并且重新核对出口，核对通过后才会再次放行。
- 同时用抓包工具（macOS 可以用 `nettop -p <Cave 的 PID>`，Windows 用 `pktmon` 或资源监视器的网络页）观察 Cave 的所有进程：内核不在的这段时间里，没有任何外网连接。

## 4. 时区和语言不跟随系统

把系统时区和系统语言改成跟 `profile.json` 不同的值，完全退出 Cave 后重开。

- 预期：自检的时区和语言两项通过。打开一个浏览器信号观察页，时区、`navigator.languages` 和 `Intl` 的值都是配置文件里的。

## 5. 地理位置

在系统设置里打开定位服务，然后访问一个会请求定位的页面。

- `geolocation` 为 null 时：预期请求被拒绝，并且系统不弹定位授权框。
- 填入坐标并重启后：预期页面拿到的是配置的坐标，系统同样不弹授权框。

## 6. UA、平台、字体

- `platform: host`：在 Cave 里和本机同主版本的 Google Chrome 里分别打开一个由你选择的浏览器信号观察页，比较 UA、`navigator.userAgentData`（包括高熵值）、`navigator.platform`、`webdriver`，以及 Worker 里的值。
  - 预期：Cave 里没有 Electron 字样，品牌里有 Google Chrome，平台和本机一致，`webdriver` 是 false。
  - 把 `window.chrome` 和其他可见差异记下来。
- `platform: windows`（在 Mac 上）和 `platform: macos`（在 Windows 上）：
  - 预期：主线程的 UA、UA-CH、`navigator.platform` 一致。
  - 已知 Worker 里的 `navigator.platform`、字体和 WebGL 不一致，自检第 13 项会标红。记下观察页报出的信号不一致项。
- 字体：在观察页的字体检测部分，记下检测到的字体。在中文系统上装一个额外字体后再测一次。
  - 已知：现在 **能** 看到额外安装的字体（见 README 的“已知限制”）。这一项用来给后续的引擎补丁做基线。

## 7. 和宿主机 TUN 共存

宿主机开着代理客户端的 TUN 模式和系统代理，并确认它本身工作正常。

- 启动 Cave 并放行。
  - 预期：Cave 的控制器端口不是 9090，`runtime.yaml` 里的端口都是随机的。宿主机客户端照常工作，两边没有端口冲突。
  - Cave 里看到的出口国家是 Cave 配置的国家；如果是串联，看到的是最终出口。
- 让宿主机 TUN 把 Cave 节点的流量导到另一个国家。
  - 预期：Cave 核对失败，保持关闭，并写明“出口国家是 XX”；宿主机 TUN 不受影响。
- 只结束 Cave 的内核，宿主机 TUN 保持开着。
  - 预期：Cave 关闭，不会因为宿主机网络还通着就继续加载。
- 在宿主机 TUN 开启的情况下，用抓包工具确认 Cave 浏览器进程没有发出 DNS 查询（包括发到 TUN 假地址段 198.18.0.0/16 的）。

- Reality 等带伪装 TLS SNI 的节点：检查宿主 TUN 的嗅探是否开启 `override-destination`。外层嗅探不能把节点 `server` 改写为伪装 `servername`。如发生冲突，在宿主客户端为节点目标添加 `sniffer.skip-dst-address` 例外并重新加载，保持 TUN、宿主节点和 Anyu 的默认系统路由不变后重测；记录修改前后结果。不要把开启 Anyu“独立连接节点”后的结果冒充默认 TUN 串联通过。

## 8. 外部观察页

外网放行后，在地址栏打开一个由你选择的浏览器信号观察页。软件不预设任何第三方观察网站。

- 预期：每个都是普通标签；自检的通过数不会因为这些页面的内容而改变。
- 这些页面上看不到本机的私网 IP 或真实公网 IP；WebRTC 只有 mDNS 候选或者没有候选；时区和语言与配置一致。
- WebGL 和字体显示本机的真实值，这是预期内的。

## 9. 浏览器功能

都在 `https://example.com` 或你常用的网站上做：

- 下载一个小文件，默认存到配置目录的 `downloads/`，工具栏的下载按钮能打开它。
- 用 `<input type=file>` 上传文件，比如在你常用的网站上传一张图片。
- 复制和粘贴：页面写剪贴板正常；页面在后台读剪贴板被拒绝。
- 打开一个在线 PDF，用内置查看器显示。
- 播放一段带声音的视频。
- 新窗口和弹窗（比如 OAuth 登录弹窗）会在新标签里打开，登录流程能完成。
- 页内查找（Ctrl/⌘+F）、缩放、打印对话框都能用。
- 通行密钥：
  - Windows：预期出现系统平台验证器。
  - macOS 未签名包：已知没有平台生物识别验证器和平台通行密钥，记录实际表现，比如是否出现“使用其他设备”或手机扫码的流程。

## 10. 暂停与重检

- 点“暂停外网”：预期内核进程消失，状态变成“已手动暂停外网”，远程导航失败。
- 点“恢复外网”：预期重新核对，通过后放行。
- 点“暂停并重检”：节点健康且国家一致时回到放行；否则保持关闭，并写明原因。

## 10b. 换节点确认与网站数据

- 选过一个节点后点另一个：弹出确认，写着两个节点的名字和“连接都会断开”；点取消，节点不变。点切换，节点变化并重新核对。
- 在你常用的网站登录后，点“清除此网站数据”：确认框写着这个网站，确认后它退出登录并重新加载；另一个网站的登录还在。
- 点“重置整个环境”：确认后所有网站都退出登录，只剩一个空白标签；环境配置、订阅、节点选择不变。

## 11. 便携配置

把整个配置目录拷到另一台机器（Mac 和 Windows 之间也可以），用 `CAVE_PROFILE` 指过去启动。

- 预期：时区、语言、国家码和节点都还在，登录状态也还在。
  - 注意：Cookie 的加密依赖系统钥匙串或 DPAPI，跨系统拷贝时登录状态可能失效，记下实际表现。
